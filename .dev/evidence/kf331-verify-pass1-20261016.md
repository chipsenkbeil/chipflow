## Rulings on the builder's three open calls

1. Nav row height 34 px against a 39 px pitch, text metrics left alone:
   REJECTED. Box pitch and inset are chrome geometry, and the error
   compounds to 50 px at the last item. That is not one of the acceptable
   deviations in VERIFIER_SPEC section 3. The text metrics are measurably
   Arial-metric 18 px (failure 4), and the project already opts single
   components into KanbanFlow's Arial metrics while leaving the app-wide
   stack alone (KF-249 legend names, KF-233 Boards button), so the nav
   and back link should do the same.
2. Colors-tab content kept its existing styling: ACCEPTED for KF-331.
   KF-331 covers the page and container chrome (H1, background, card
   styling), and the Colors content was already worked through
   KF-080..087 and KF-107..111. The remaining content gap is real and
   untracked, so it is filed as a new defect: rows render as bordered
   cards where KanbanFlow has a table with a `#f5f5f5` header row
   (Color / Name / Actions) and `#dddddd` row rules, and the intro box
   is `#eff6ff` with a `#bfdbfe` border where KanbanFlow uses `#d9edf7`
   with `#bce8f1`.
3. KanbanFlow's dark global top bar not reproduced: ACCEPTED for KF-331.
   The baseline board settings page on `6c3a9e0` has no top bar either
   (`#eef0f3` at (10,10), (960,10), (10,30) of
   `main-colors-1920x1000.png`), so the branch removed nothing, and the
   recovery doc's mismatch table does not list it. ChipFlow does draw the
   KanbanFlow-style bar on the board page
   (`cand-board-1920x1000.png`), and the reference shows it on board
   settings, so the gap is filed as a new defect.

## Unrelated finding

`routes::tests::format_due_card_weekday_near_absolute_far` and
`routes::tests::format_due_modal_relative_and_done_marker`
(`src/routes.rs:7433`, `:7462`) fail on any host whose local zone is not
UTC. The formatters render in server-local time, and the tests format a
local wall-clock string and then append a literal `Z`. Europe/London (BST)
renders `6:00 PM` and America/Chicago `12:00 PM` where the tests expect
`5:00 PM`. `TZ=UTC cargo test` passes 96 of 96. Test-only bug, app code
correct, not part of KF-331.
