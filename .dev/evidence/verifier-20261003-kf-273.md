## Root cause

`static/app.js` `moveSubtask()` (KF-273 code):

```js
api('/api/tasks/' + encodeURIComponent(taskId) + '/subtasks/order', 'PUT', { order: order })
  .then(function (res) {
    if (!res.ok) { /* revert + toast */ return; }
    modalDirty = true;
  });
```

`api()` returns the raw `fetch()` promise with **no `.catch()`**. HTTP error
statuses are handled (`!res.ok`), but a fetch-level rejection (network down,
aborted request, DNS) skips the revert entirely: the DOM keeps the swapped
order while the server never applied it, no toast informs the user, and the
rejection surfaces as a console pageerror. The builder's evidence claimed
"revert + toast on failure"; the network-failure case was evidently never
tested. Fix is small: add `.catch()` performing the same revert + toast.
