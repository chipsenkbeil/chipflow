## Fixture note (contract-repro gap, not a KF-242 product defect)
`POST /api/tasks` (`CreateTaskInput`) has NO `description` field — the
fixture's `description=` body param is silently ignored (serde unknown-field
drop). Description must be set via `PATCH /api/tasks/{id} {"description": …}`
(`UpdateTaskInput.description` exists). The contract's "POST /api/tasks a
task with description text" repro step is therefore unachievable literally;
the repair's verification used POST + PATCH. Also note: the round-2
verifier's "5 icons" presence PASS could not have come from its fixture
script alone (same silent drop); its screenshot shows the doc icon, so the
description must have reached the DB by another path. This repair verified
presence/order against a task with all five attributes genuinely set.
