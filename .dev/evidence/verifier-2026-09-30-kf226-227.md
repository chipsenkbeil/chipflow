## 4. Builder's wip_limit finding: CONFIRMED

> "`UpdateColumnInput.wip_limit: Option<Option<i64>>` has the same stock-serde
> null-collapse bug — its doc comment claims JSON null clears the limit but
> `{"wip_limit": null}` deserializes to absent → unchanged."

- Evidence: column with `wip_limit: 5` set via `PATCH {"wip_limit":5}` (200, GET confirms 5) →
  `PATCH {"wip_limit":null}` → **200** → GET columns still shows `wip_limit: 5`.
- Root cause in `src/routes.rs:3877`: `wip_limit: Option<Option<i64>>` has NO
  `#[serde(default, deserialize_with = ...)]`, and `de_opt_opt` is `String`-only,
  so stock serde collapses JSON `null` to `None` (same as absent) and
  `if let Some(wip_limit) = input.wip_limit` (line 3923) is skipped. The doc
  comment "`Some(None)` (JSON null) clears the limit; absent leaves it alone"
  is false, and the OpenAPI schema for `UpdateColumnInput.wip_limit` also
  carries the false "clears the limit" description.
- This is a pre-existing bug, independent of the KF-226/227 builder's changes.
  Not filed here per instructions — handed to the orchestrator.
