## 4. Pre-existing finding (NOT filed as a defect — out of scope, predates the builder)

`DueDateDialog.clear()` sends `PATCH {"due_at": null, "due_repeat": null}`, but `UpdateTaskInput.due_at: Option<String>` (`src/routes.rs:1763`, documented "empty string clears it. Absent leaves it unchanged") deserializes JSON `null` as absent, so the server returns 200 and **silently leaves the due date unchanged**. Verified via curl: null-clear → `due_at` unchanged; `""`-clear → `due_at: null`. The UI Clear button is therefore a server-side no-op today. Untouched by the builder's diff (both the JS `clear()` and the server handler predate it); the KF-225 fix (staleness on save) is unaffected. Recommend the orchestrator file this as a new KF defect (server: treat JSON null like empty string, or dialog: send `""`).
