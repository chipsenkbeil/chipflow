# Builder evidence — KF-273 (2026-10-03)

## Per-unit contract (BUILD_CONTRACT §1)

1. **What changes, with exact expected values:**
   - `static/app.js` `wireSubtasks()`: replace the wrap-level keydown handler with one that
     implements the shortcuts documented at `templates/board.html:1061-1062`
     ("↑ ↓ — Navigate subtask list", "Cmd + ↑ ↓ — Move subtask in list"):
     - Plain `ArrowUp`/`ArrowDown` with focus anywhere inside a `.tm-subtask` row
       (name span, checkbox, handle — but NOT inside the inline `.tm-subtask-edit`
       input, where arrows are caret navigation) moves focus to the previous/next
       row's `.tm-subtask-name`. `preventDefault()` so the page/modal doesn't scroll.
       No-op at the list ends.
     - `Ctrl`+↑/↓ or `Cmd`(metaKey)+↑/↓ moves the focused row one position up/down in
       the DOM and persists the new order via `PUT /api/tasks/{id}/subtasks/order`
       with body `{"order": [<subtask ids in DOM order>]}`. Focus stays on the moved
       row's name. On API failure the DOM swap is reverted and a toast appears.
   - `src/db.rs`: new `reorder_subtasks(task_id, order: &[String]) -> DbResult<bool>` —
     sets `task.subtasks` to the given id sequence (ids in `order` that exist, in
     given order; any current subtasks not mentioned are appended in original
     relative order so a partial list can never silently drop subtasks). Returns
     false when the task does not exist.
   - `src/routes.rs`: new `PUT /api/tasks/{id}/subtasks/order` handler with full
     `#[utoipa::path]` annotation (OpenAPI generated from it), same auth as the
     other subtask endpoints. Responds 200 with the reordered subtask id list;
     404 when the task does not exist.
   - `agents.md` / `agents/skill.md`: one-line doc for the new endpoint
     (AGENTS.md rule: keep agent docs accurate when API behavior changes).
2. **Golden masters:** GM-086 (↑/↓ moves focus between subtask rows), GM-149,
   GM-150 (Cmd+↑/↓ reorders the focused subtask, order persisted). All text-source
   (`.dev/evidence/kf-drafts/kf-draft-v3-GM-086.md`,
   `kf-draft-v4-GM-149.md`, `kf-draft-v4-GM-150.md`); judged by behavior + screenshots,
   not pixdiff.
3. **Fixture:** task modal with 3 subtasks ("sub-one", "sub-two", "sub-three");
   focus a `.tm-subtask-name`; press ↓/↑ and Ctrl+↓/Ctrl+↑ (headless = Ctrl; macOS Cmd).
4. **Out of scope:** drag reorder (doesn't exist); card inline-list ordering
   (card shows undone-first, separate KF concern); collapsed/expanded card lists;
   the shortcuts dialog text itself (already verbatim).
5. **Regression expectations:** Enter-to-edit, checkbox toggle, delete menu,
