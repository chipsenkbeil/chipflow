## Defect
Every board task card rendered a 1px border in near-black (31,41,55) instead of the
color-matched border shade of its card color.

## Root cause (confirmed in code)
`static/style.css`: the `.task-card { border: 1px solid; }` base rule sorted AFTER
the `.taskBorderColor-*` rules at equal specificity (one class each). The `border`
shorthand resets `border-color` to `currentColor` (near-black), defeating the
per-color `border-color` declarations.

## Fix
Replaced the shorthand with `border-width: 1px; border-style: solid;` in
`.task-card` (+ comment crediting KF-245). Width/style are set without touching
`border-color`, so the `.taskBorderColor-*` class always wins regardless of cascade
order. No color hexes changed; behavior for cards without a taskBorderColor-* class
(currentColor fallback) is identical to before. `body.dark .task-card
{ border-color: #4b5563; }` (higher specificity, later) is untouched.
