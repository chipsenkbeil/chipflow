### Instrument hazard found and corrected (shared cargo build dir)
`~/.cargo/config.toml` sets `build.build-dir = "{cargo-cache-home}/build"`, which every worktree shares. My first baseline `cargo build --release` finished in 0.19s and produced a binary **byte-identical to the fix binary** (md5 `6dfad177…`). Its served CSS also contained the fix's `.board-settings-page` rules. Static files are embedded at compile time in release builds, so a stale shared build dir silently serves the wrong tree. I discarded that instance and rebuilt both trees with `--config 'build.build-dir="target/build"'`:
- Baseline md5 `6770ede045dc551efee02e35e340f723`. Served CSS has 0 matches for `board-settings-page`.
- Fix md5 `6dfad177eb91bc495ad1689a81012d17`, the same as the first build, so the fix binary was genuine. Served CSS has 4 matches.

This hazard can make any worker's baseline-vs-fix comparison meaningless. It should be filed separately.
