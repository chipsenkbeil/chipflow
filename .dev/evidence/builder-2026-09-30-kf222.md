# KF-222 builder report — 2026-09-30

Defect: the Pomodoro legend footer rendered on every board; generic
KanbanFlow shows no footer unless a per-board "Color legend" toggle is on.

## Key design decision (read first)

The spec asked for a new per-board `color_legend` boolean, but a
`legend_visible` mechanism already existed from KF-183 (Menu checkbox +
`PUT /api/boards/{id}/config` + template context + `BoardRow::config_bool`) —
the footer simply ignored it. I **reused `legend_visible`** instead of adding
a parallel `color_legend` key: two keys would be two sources of truth for one
toggle. Observable behavior matches the spec exactly; only the config key
name differs.

## Changes (all uncommitted, `~/workspace/pomodoro-kanban`, master)

- `src/routes.rs` — added `ColorView::legend_label()`: the color's custom
  label, falling back to `standard_name` when empty (labels are validated
  non-empty, so the fallback is defensive).
- `templates/board.html` — footer is now guarded by
  `{% if legend_visible %}` and renders **all enabled** board colors in
  palette order via `{{ color.legend_label() }}`. Removed the hardcoded
  `label.contains("Pomodor")` filter — the footer is generic, never keyed to
  seeded names. When OFF, **no footer markup at all** is emitted.
- `src/db.rs` —
  - `migrate_legend_default()`: one-time lazy backfill (missing key → `true`,
    explicit `false` preserved), guarded by a `legend_backfill_done` marker in
    the SETTINGS table so it runs exactly once. Called in `connect()` **before**
    `seed()` so a fresh install's starter "General" board defaults OFF.
    (The marker exists because a plain "backfill where missing" pass would
    re-fire on the fresh install's second boot and flip the seeded board ON.)
  - `#[cfg(test)] mod legend_migration_tests`: regression test covering
    backfill-grants-true, exactly-once, explicit-false preserved, new boards
    default OFF.
- `static/app.js` — rewrote `toggleLegend()`: reads the target state from the
  menu item's `aria-checked`, PUTs `{legend_visible}`, reloads on success so
  the server renders/omits the footer. Removed the optimistic hidden-toggle
  + scroll/flash behavior (impossible when OFF emits no markup).
- `static/style.css` — removed the now-unused `.legend-flash` class.
- `agents.md` — documented footer semantics in the config-bag section.
  `agents/skill.md` needed no change (its one-liner was already accurate);
  no API routes changed (`BoardConfigInput.legend_visible` already annotated).

## Verification (test instance :3105, fresh redb at `/tmp/chipflow-kf222.redb`)

1. **New board → no footer by default.** Fresh DB, seeded "General": board HTML
   contains 0 `<footer class="color-legend">` elements; Menu item
   `aria-checked="false"`. Screenshot:
   `.dev/evidence/kf222-a-no-footer.png`
2. **Toggle ON → 8 labeled segments.** Disabled brown + white via
   `PATCH /api/boards/{id}/colors/{colorId} {"enabled":false}`, then clicked
   ≡ Menu → "Color legend" in headless Chromium (page reloaded). Footer shows
   8 segments in palette order with custom names:
   `1 Pomodoro, 2 Pomodori, 3 Pomodori, >3 Pomodori, Orange, Purple, Magenta,
   Cyan`; menu `aria-checked="true"`. Screenshot:
   `.dev/evidence/kf222-b-footer-on.png`
3. **Rename reflected.** `PATCH .../colors/{yellowId} {"label":"Deep work"}` →
   footer first segment reads "Deep work". Screenshot:
   `.dev/evidence/kf222-c-renamed-color.png`
4. **Explicit OFF survives restart.** `PUT .../config {"legend_visible":false}`,
   restarted :3105 → still 0 footer elements, `aria-checked="false"` (marker
   prevents the backfill from re-firing).
5. **Migration unit-tested.** The regression test simulates a pre-upgrade boot
   (marker dropped, keyless board) and asserts the backfill grants `true`
   once, never overwrites explicit `false`, and leaves new boards OFF.
