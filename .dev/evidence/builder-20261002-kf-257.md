# Builder evidence — KF-257: Color row shows only the dot, missing the color name text

**Date:** 2026-10-02 · **Commit:** `b2f987a` ("Show color name next to dot in task modal Color row (KF-257)") · **Branch:** master

## Defect
Task modal Color row rendered only the color dot. KanbanFlow renders "● Orange" — dot followed by the color name (GM-073-modal-open.png).

## Approach
- `templates/modal.html`: added `<span class="tm-color-name">{{ task.color_label }}</span>` immediately after the `.tm-color-chip` dot button in the `data-cell="color"` cell. The dot remains the sole color-picker trigger; the name is plain text. `color_label` resolves through the board's color config ("Orange" for the orange color), so it matches KanbanFlow's label exactly. Empty-label case renders an empty span (no visible text); colors are always backfilled so the label is non-empty in practice.
- `static/style.css`: `.tm-color-name` already existed as an unused class (`0.9rem`, `var(--ink)`); changed its color to `#333333` — the golden text core measured at (51,51,51) in GM-073. Added `.tm-cell[data-cell="color"] .tm-cell-value { display: inline-flex; align-items: center; gap: 5px; }` so dot + name sit on one baseline.
- `static/app.js` (`setModalColor`): after a picker color change, the name span text and the dot's `title` now update to the new color's label (previously only the CSS var class changed, leaving a stale name). Also refreshed the stale KF-073 comment.

No new dependencies. Blast radius: the Color row cell only; no other modal row touched.

## Repair round 2 (2026-10-02, repair worker) — verifier FAILED the default case

**Root cause (different from first impression):** the verifier was right that the default case rendered "● 1 Pomodoro", but the mechanism was subtler than "unconditional span". ChipFlow's `POST /api/tasks` assigns every new task the board's **default color row** (`color_id` = default id, `routes.rs` `create_task`: "otherwise the task gets the board's default color"). So the "no-color/default case" is *not* `color_id = None` — it is `color_id == board default` (seeded yellow row, label "1 Pomodoro"). Any fix keyed on `color_id.is_none()` would have missed the real default case entirely.

**Fix:** the modal now shows the color name iff the task's resolved color is **not** the board's default color (`TaskView.show_color_name`, computed in `task_color_view` from `ColorRow.is_default`):
- `src/routes.rs`: `task_color_view` returns `(ColorFields, show_name)` where `show_name = !resolved.is_default` on both the explicit and legacy paths (false on the no-rows fallback); `TaskView` gains `show_color_name: bool` (false in `from_row`, resolved in `from_row_in_board`).
- `templates/modal.html`: name `<span>` and the `"label — click to change"` chip title render only when `task.show_color_name`; default case gets `title="Click to change"` and dot-only.
- `templates/board.html`: hidden `#board-colors` palette spans now carry `data-default` (from `ColorView.is_default`); `static/app.js` `buildModalColorPicker` copies it to the picker dots, and `setModalColor` keeps the invariant live: picking a non-default color creates/updates the name span; picking the default removes the span and neutralizes the chip title.
