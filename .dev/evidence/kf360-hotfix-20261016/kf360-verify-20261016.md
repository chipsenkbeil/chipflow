The three it doesn't are a one-task column, the clear attempt that writes nothing, and the s19 re-save; s19 still fails on the baseline, because the save hits the wrong tasks. ## Method
- `snapshot.sh` captures every task on every board from `/api/boards/{id}/export-data`.
  - Fields: `due_at`, `due_repeat`, `due_done`, column and board.
  - It checks the task set against `GET /api/tasks` and the due fields against each task's `GET /api/tasks/{id}`, and aborts on any mismatch.
- `run.sh` snapshots before, drives the scenario, snapshots after, and diffs.
  - `due_at` is compared as an instant. A column change also counts as a change.
  - A scenario is OK only if no task outside the expected set changed and each expected task equals its expectation and stayed in its column.
- `drive.mjs` uses the real UI: card click or `#task-` deep link, Add menu → Due date or the due chip, inline calendar day click (with month navigation), the time field, the Target column select and the Repeat checkbox, then Add.
  - It logs console errors, page errors, failed requests, responses of 400 or above, and every PATCH sent to `/api/tasks`.

## Observations (not failures of KF-360)
1. **The UI cannot clear an existing due date.** `#dd-date` is readonly. Meta/Ctrl+A, Backspace and Delete leave the value unchanged, Playwright `fill('')` times out on the readonly field, and the dialog has no Clear button (its buttons are `<`, `>`, the day numbers, Today, yesterday, This month, Cancel, Add). Only a task that has no date can send `due_at: null` (s06).
2. **s18 is a server behaviour that predates the fix, and it affects only the open task.** The `due_done` reset in `src/routes.rs` (~2097, `if due_at != existing.due_at`) compares strings. A seeded or API-written `...08:00:00Z` re-sent by the dialog as `...08:00:00.000Z` counts as a change and resets `due_done`. s19 shows a date written by the UI (`.000Z`) keeps `due_done`. This is a candidate new defect.
3. **The Target column select now has no effect.** The fix ignores it, and nothing stores the due date's target column, which the defect's fix direction mentioned as optional. The KanbanFlow "target column" semantics are still unimplemented.
4. When a task from another board is opened by deep link (s16), the dialog lists the current board's columns. This is harmless now that the select is ignored.
5. Double-clicking Add sends two identical PATCHes, so there is no in-flight guard. The result is still correct.
6. The release build warns about an unused import (`tower_http::services::ServeDir`, `src/routes.rs:26`). It predates the fix, since `src/` is unchanged.
7. The modal and cards show times in the server's timezone (BST), so 07:05Z displays as 8:05 AM. That is because I ran the browser in UTC, not a defect.
